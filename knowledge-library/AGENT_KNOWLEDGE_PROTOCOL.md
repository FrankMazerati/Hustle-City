# Hustle City Agent Knowledge Protocol

All human collaborators, assistants and production agents must treat the repository knowledge library as the shared project memory.

## Before starting a task
1. Read the knowledge library home and index.
2. Read the framework(s) relevant to the assigned domain.
3. Check the decision register for approved rules and unresolved questions.
4. Check existing project documents before creating a duplicate specification.
5. Identify conflicts between new instructions and existing approved decisions; escalate instead of silently choosing.

## During work
- Preserve the creator's intent and exact approved terminology.
- Separate facts, creator-approved decisions, proposals, assumptions and open questions.
- Never turn an assistant/agent suggestion into an approved project rule without creator approval.
- Link source conversations, images, research and related documents where available.
- Do not claim code, assets, agents, builds or deployments exist unless verified.

## When a new idea appears
1. Add it to ideas/INBOX.md using the capture format, preserving original wording.
2. Assign a domain and status.
3. If it affects an existing framework, add a clearly marked proposed section or prepare a revision for review.
4. If the creator approves it, record the decision in DECISION_REGISTER.md and update the relevant framework.
5. Update INDEX.md when a new major document or framework is created.
6. Keep superseded material and link to the replacement.

## Deliverable handoff
Every substantial agent handoff should include:
- Documents read
- Work completed
- Files changed
- Decisions relied upon
- New ideas captured
- Questions requiring creator direction
- Verification performed and limitations

The knowledge library is the source of truth for design intent; implementation repositories and tests remain the source of truth for actual technical status.
