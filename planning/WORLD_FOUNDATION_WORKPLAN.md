# Hustle City — World Foundation Workplan

**Status:** Active planning work package; no playable build or agent activation implied.  
**Owner:** Creator / Visual Director and Game Architect, with Trinity coordinating future work.  
**Primary engine:** Unreal Engine 5. **Secondary target:** Unity 6.

## Goal

Use the download/setup waiting period productively by completing the engine-neutral design foundation that future agents and production tools will consume.

## Work package A — establish the map canon

1. Collect the earliest map conversations, screenshots, and reference photos.
2. Compare the original map references with the current repository's 7×7 / 43-outer-box planning-envelope note.
3. Confirm the six central district identities and positions.
4. Confirm the arrangement and count of all outer neighborhood boxes.
5. Define stable IDs and naming conventions for districts, neighborhoods, blocks, and transport nodes.
6. Publish the approved master-map envelope and unresolved-items list.

**Exit condition:** Creator-approved map layout and a clear separation between confirmed geography and provisional capacity assumptions.

## Work package B — reserve the transportation skeleton

1. Reserve the HIM intercity terminal and approach corridor(s).
2. Reserve HCTA corridors connecting the six central districts.
3. Ensure every outer neighborhood has HCTA station access.
4. Mark candidate HIM/HCTA transfer locations.
5. Reserve elevated, underground, and street-level operating sections where the geography supports them.
6. Coordinate rail with the Skyway, ground expressway, arterial roads, waterways, pedestrian paths, and station access.

**Exit condition:** A route-and-station framework with no invented route metrics or unapproved line count.

## Work package C — define district and neighborhood envelopes

For each district and neighborhood, create a structured record with:
- stable ID and display name;
- status (approved, working label, proposed, unresolved);
- boundary reference;
- visual identity and environment profile;
- major roads and transit access;
- landmarks and civic spaces;
- planned venues and activity anchors;
- block/parcel references;
- ownership, residency, and crew relationships kept separate.

**Exit condition:** Every map area can be described consistently without confusing geography with player ownership.

## Work package D — prepare downstream production packages

Create engine-neutral specifications before engine-specific work:
- map coordinate and scale conventions;
- road and rail corridor manifests;
- station and transfer manifests;
- district/neighborhood metadata;
- asset and reference provenance;
- integration contracts for UE5 and Unity 6.

**Exit condition:** The production teams can work from one versioned specification instead of separate interpretations.

## Current work boundaries

This work package does **not**:
- claim a playable or viewable city has been built;
- create Unreal or Unity project assets;
- activate or dispatch autonomous agents;
- deploy or modify a live Supabase project;
- lock unresolved district names, route names, station locations, route count, or neighborhood count;
- treat old screenshots or generated images as final map authority without creator review.

## Immediate next inputs

The highest-value material to reconcile is:
1. the first Command Center review conversation;
2. the earliest overhead map and district layout screenshots;
3. later corrections to district identities, neighborhood boxes, and transit;
4. the opening train-arrival sequence and related story decisions.

Once those are available, update the master geography blueprint and transportation specification, then create the first structured district/neighborhood/rail manifests.
